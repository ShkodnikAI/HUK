### Fact base (Auditor, read on `main`; not run)

- `src/components/player/radio-player.tsx` (592 lines) is one client component that does everything: polls `/api/radio/now`, corrects drift, applies regional restrictions through `/api/geo`, sends listen start/beat, reads and writes reactions (`/api/me/reactions`, `/api/reactions`), switches between radio and "My playlist" mode, and shows a native `<select>` for playlists and a `<details>` "Add to playlist". The UI is bare: a play button, the title, a Like button. It sits in the footer of the locale layout.
- The home page is a placeholder text. There is no dislike button in the UI although `POST /api/reactions` accepts a private DISLIKE.
- `RadioNowTrack` (`src/lib/radio/contract.ts`) carries `id, title, artist, durationSec, audioUrl, restrictedIn, likes` but not the language, the instrumental flag or whether the track is AI-generated; those columns exist on `Track` (`language`, `instrumental`, `aiGenerated`). `/api/radio/now` is a pure read, one SQL query, identical for every listener and cached 2 s: it must stay that way.
- Playlist APIs are merged (`/api/playlists`, `/api/playlists/[id]`, `.../items`, `.../import`, H-302); playlist playback honours `licenseScope`. There is no playlist screen.
- Boards: `Main.dc.html` (phone radio), `DesktopRadio.dc.html`, `Playlists.dc.html`. The comment ticker on `Main` is delivered by a later naryad after the comments API exists (H-303); here you only reserve its slot.

### Task

1. **Split the player.** Move the audio engine (the `<audio>` element, timeline sync, drift correction, retries, geo restrictions, listen heartbeat, Media Session, playlist playback) into a provider mounted once in the locale layout, exposing state and actions through a typed hook. Views read the hook. This is a refactor first: behaviour must not change, and the existing tests (`tests/sync*`, `tests/listen-client.test.ts`) must pass unchanged.
2. **Radio screen** at `/[locale]` per `Main.dc.html` (phone) and `DesktopRadio.dc.html` (1024 px and up): LIVE badge with "One shared timeline for everyone", the now-playing card (progress from the server timeline, title, artist name, chips for language and "AI-assisted" when declared, the instrumental chip), large play/pause, Like and private Dislike buttons with the 30-second lock explained in words (the existing lock logic stays), "Add to playlist" (a proper menu or sheet instead of `<details>`), "Report" (links to the report page only if it exists, otherwise not rendered; the report form itself is not in this naryad), the Radio / My playlist switch. The artist name is plain text until the artist profile route exists. The Dislike button shows no count and no state to anyone else; the Like count shown is the public one from `/now`.
3. **`/now` contract.** Add `language: string | null`, `instrumental: boolean` and `aiGenerated: boolean` to `RadioNowTrack` and to the existing single SQL statement; the response stays identical for all listeners, a pure read, at most 2 queries (the existing test is extended). AUDIUS and other URLs are untouched.
4. **Quiet state.** When `/now` has no current track, show the `QuietState` from H-120. When a track fails to play, keep the current retry behaviour and show the existing "waiting for the next one" message in the new style.
5. **Playlists screen** at `/[locale]/playlists` per `Playlists.dc.html`: list, create, rename, delete, open a playlist, reorder items (the PATCH route), remove an item, unavailable items marked in words, "Play" starting playlist mode. Guest playlists keep working through the existing local-first sync (`src/lib/sync`); after sign-in they are imported through `/api/playlists/import` as today. Limits (50 playlists x 500 tracks) shown in the user's language when reached. Turn on the Radio and Playlists navigation flags from H-120.
6. **Tests:** engine/view split keeps one `<audio>` and survives navigation; reaction lock and private dislike (no count rendered anywhere); `/now` extension; playlist screen states (empty, unavailable item, limit reached); axe checks; all strings in both catalogs.
