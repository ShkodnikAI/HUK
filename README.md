# HUK — круглосуточная интернет-радиостанция с ИИ-модерацией

HUK — это интернет-радио 24/7, где эфиром управляет не человек, а виртуальная шкала
времени на сервере: все слушатели в один и тот же момент слышат один и тот же трек.
Слушатели загружают свои композиции, трёхслойный ИИ-конвейер модерации проверяет их
(техника → транскрипция речи → LLM-политика станции), а одобренные треки попадают
в плейлист «Свежак от слушателей» и в общую ротацию. Эфир озвучивает ИИ-диджей
ВЕКТОР своими джинглами.

## Принципы станции

1. **Единая шкала времени эфира.** Станция ведёт бесконечную цепочку сессий
   (`BroadcastSession` с серверными метками `startedAt`/`endedAt`). Клиенты
   синхронизируются по `serverTime` с коррекцией дрейфа — «перемотка» в прямой
   эфир невозможна, все слышат одно и то же.
2. **Смена плейлиста — только на стыке треков.** Выбор нового плейлиста ставит
   отложенную метку `pendingPlaylistId` и применяется между композициями, эфир
   не рвётся на середине песни.
3. **Модерация с полным аудит-логом.** Каждый вердикт ИИ (и каждого человека)
   сохраняется: транскрипт, категория нарушения, уверенность, доказательства.
   Авто-решение принимается только при confidence ≥ 0.75, спорное уходит человеку.
4. **Контент без копирайта.** Вся сид-музыка генерируется процедурно
   (`scripts/gen_music.py`), джинглы синтезируются голосом (`scripts/gen_jingles.py`,
   espeak-ng + радиоеффекты + музыкальная подложка из собственных треков).

## Архитектура

```
src/
  lib/radio.ts          — эфирный движок: виртуальная шкала времени, очередь «Далее»,
                          джингл каждые 4 песни, достройка цепочки сессий вперёд
  lib/moderation.ts     — ИИ-конвейер модерации:
                          Слой 1 техника: ffprobe (длительность 15с–12мин) + volumedetect (тишина)
                          Слой 2 ASR: транскрипция первых 60 секунд (z-ai-web-dev-sdk)
                          Слой 3 LLM-политика: 8 категорий нарушений, JSON-вердикт
  hooks/use-radio.ts    — синхронный плеер: поллинг 8с, skew-коррекция, дрейф 3с,
                          heartbeat слушателя 10с, Web Audio визуализатор
  components/radio/     — вкладки Эфир / Загрузить / Модерация
  app/api/
    radio/now           — текущий момент эфира (трек, очередь, слушатели, статистика)
    radio/switch        — смена плейлиста (на стыке треков)
    radio/heartbeat     — пульс слушателя (подсчёт уникальных)
    media/[id]          — стриминг с HTTP Range (206 Partial Content)
    upload              — приём композиций от слушателей (multipart, XHR-прогресс)
    tracks/[id]         — карточка трека и статус модерации
    my-tracks           — треки текущего слушателя
    playlists           — список тематических плейлистов
    moderation/queue    — очередь на ручную модерацию
    moderation/decide   — вердикт человека (approve/reject)
prisma/schema.prisma    — Track, Playlist, PlaylistTrack, BroadcastSession,
                          StationState, ModerationLog
upload/radio/           — медиатека станции: seed/*.mp3 (9 процедурных треков),
                          jingle_*.mp3 (4 джингла ВЕКТОРА), тестовые файлы модерации
db/custom.db            — SQLite: текущее состояние эфира и контента
```

## Стек

- **Next.js 16** (App Router) + **React 19**, Tailwind CSS 4, shadcn/ui
- **Prisma** + SQLite (без внешней БД — станция поднимается одной командой)
- **z-ai-web-dev-sdk** — ASR-транскрипция и LLM-вердикт модерации
- **ffmpeg / ffprobe** — технический слой модерации и радиоеффекты джинглов
- **espeak-ng** — голос ИИ-диджея ВЕКТОРА
- **numpy/scipy** — процедурная генерация сид-музыки (синтвейв 88 BPM,
  лофай 72 BPM, танцпол 124 BPM)

## Запуск

```bash
bun install
cp .env.example .env          # DATABASE_URL уже указывает на file:./db/custom.db
bunx prisma db push           # если БД нет — создаст схему
bun scripts/seed-radio.ts     # сид: 4 плейлиста, 13 треков, состояние эфира
bun run dev                   # http://localhost:3000
```

Требования: `bun`, `ffmpeg`, `ffprobe`, `espeak-ng` (для джинглов), Python 3 с
numpy/scipy (только для регенерации музыки).

Регенерация контента станции:

```bash
python3 scripts/gen_music.py      # 9 процедурных треков → upload/radio/seed/
python3 scripts/gen_jingles.py    # 4 джингла ВЕКТОРА → upload/radio/
```

Сид идемпотентен: если плейлисты уже есть, повторный запуск пропускается.
Для полного сброса — удалить `db/custom.db` и повторить `db push` + сид.

## Дорожная карта доработки (по шагам)

1. Относительные медиа-пути: БД хранит абсолютные пути `upload/radio/...` —
   перевести на относительные от корня проекта (переносимость деплоя).
2. Приёмник внешнего потока: совместимость с Icecast-клиентами (LIQ/OBS),
   чтобы живой ведущий мог вклиниваться в эфир.
3. Расписание эфиров: таймблоки «синтвейв — после полуночи», анонсы ВЕКТОРА
   перед сменой блока.
4. Профили слушателей: история прослушиваний, избранное, личные плейлисты.
5. Лимиты и антиспам загрузок: rate limit по UID, квоты на сутки, дедуп по
   аудио-отпечатку.
6. Нейроголос ВЕКТОРА: перейти с espeak-ng на полноценный TTS с русским
   произношением и подкаст-интонациями.
7. Деплой: контейнеризация, постоянный том для `upload/radio/` и БД,
   health-check `/api/radio/now`.
